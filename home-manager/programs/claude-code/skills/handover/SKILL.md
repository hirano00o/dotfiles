# セッション引き継ぎノート生成

セッション終了時や作業の区切りで、引き継ぎノートを生成する。

## 手順

1. 今回のセッションで行ったことを振り返る
2. Bash で書き込み先ディレクトリを確定して作成する:
   ```bash
   mkdir -p "$HOME/.claude/handovers/$(basename "${CLAUDE_PROJECT_DIR:-$PWD}")" && echo "$HOME/.claude/handovers/$(basename "${CLAUDE_PROJECT_DIR:-$PWD}")"
   ```
   出力された絶対パスを以後の Write ツール呼び出しに使う（`$HOME` や `~` のままでは Write で展開されないため、必ず展開後の絶対パスを渡す）
3. ファイル名は `date +%Y-%m-%d_%H%M%S` を実行した結果から `YYYY-MM-DD_HHmmss.md` とする（例: `2026-02-17_143052.md`）。時刻を記憶から書いたり丸めたりしない
4. 同名ファイルが既にある場合は `date` を再実行し、秒が進んだ新しいファイル名を使う

## 引き継ぎノートの構成

必ず以下のセクションを含める。該当なしのセクションは「なし」と記載する。

### 今回やったこと

- 作業内容と進捗を箇条書きで

### 決定事項

- 確定した設計判断、方針、ルールなど

### 捨てた選択肢と理由

- 検討したが採用しなかったアプローチとその理由

### ハマりどころ

- 詰まったポイント、エラー、想定外の挙動など

### 学び

- 今回得られた知見、気づき

### 次にやること

- 未完了のタスク、次のセッションで着手すべきこと
- 優先度は `### 優先度: 高` / `### 優先度: 中` / `### 優先度: 低` の小見出しでグループ化する（項目が少なければ行頭に `(優先度: 高)` を付す形でもよい）

### 関連ファイル

- 今回触った主要ファイルのパス一覧
- PR やプラン文書に紐づく作業では「### 関連PR」「### 関連プラン」を下位見出しとして置く

## ルール

- 簡潔に書く
- 箇条書き中心
- 推測や曖昧な表現は避け、事実ベースで書く
- 「捨てた選択肢と理由」は特に重要。次のセッションで同じ議論を繰り返さないために
- 同一作業の連続セッションでは、冒頭に「前回ノート (`ファイル名`) からの差分」の一文を置き、差分中心に書く。長期作業では「## 履歴サマリ (累計)」を任意で置ける

## 良い例 / NG 例

良いノートの特徴 (過去ノートの実績より):

- 「捨てた選択肢と理由」をカテゴリの小見出しで構造化する
- 捨てた理由に「ソースを確認した事実」を添える (例: 「`_attach` (doc.lua:441) はグローバル config しか読まないため不採用」)
- 「ハマりどころ」にファイル名・行番号・再現条件を残す

NG パターン:

- 「なし」を並べただけの形式的なノート。単純作業のセッションでは「今回やったこと」と「次にやること」を具体的に書き、他セクションの「なし」は 1 語で済ませてよい
