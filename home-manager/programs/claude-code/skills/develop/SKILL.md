# 開発ワークフロー

引数 (`$ARGUMENTS`) があればそれを今回のスコープとする。無ければ要件ドキュメント
(REQUIREMENTS.md 等) から「着手できていない要件・未修正の指摘」を洗い出し、
今回どこまで進めるかを提案してから着手する。

## 手順

1. **スコープ決定**: 今回進める範囲を決め、TodoWrite で作業リスト化する
2. **ブランチ作成**: main / master から作業ブランチを切る (直接コミット禁止)
3. **設計**: 実装方針を短くまとめる。非自明な判断は選択肢と理由を明示する
4. **TDD 実装**: impl サブエージェントに単機能ずつ委譲する。tdd-cycle の
   Red → Green → Refactor → Type/Check → Lint → Format を厳守
5. **レビュー**: code-review スキル (またはレビューエージェント) で変更をレビューする
6. **修正**: レビュー指摘を修正する
7. **反復**: 指摘がゼロになるまで 5–6 を繰り返す
8. **出荷**: ship スキルで commit → push → PR 作成まで行う

## ガード

- サブエージェントを積極的に活用し、メインコンテキストを設計判断と進行管理に使う
- 実装変更に伴う要件ドキュメント (REQUIREMENTS.md 等) の更新は**同一コミット**に含める
- レビュー指摘が残った状態で PR を作らない
- スコープ外の改善は TodoWrite に記録して混ぜ込まない
